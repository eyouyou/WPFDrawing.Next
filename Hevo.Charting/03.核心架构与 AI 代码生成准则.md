## 🧠 一、 核心架构哲学 (Core Philosophy)

1. **极限性能与 0-GC**：引擎针对千万级数据点设计，底层数据流转和物理快照必须尽可能做到 0-GC。强制使用 `ArrayPool` 复用、原位更新 (In-place Update)、以及列式内存布局 (SoA)。
2. **纯自研 Rx 管线**：全盘禁止使用 `System.Reactive`。我们拥有绝对控制权的自研轻量级流式引擎 `IWorkflow<T>` 和管线构建器 `DataPipeBuilder`。
3. **宏观并发控制**：绝不迷信“无锁 (Lock-Free)”。由于图表指标需要保证多引脚的“时空一致性”，我们采用宏观的 `ReaderWriterLockSlim` 来保证事务的绝对安全。

## 🏗️ 二、 四大核心基建规范 (Core Infrastructure)

#### 1. 状态黑板 (DataBlackboard)
* **职责**：图表唯一的数据真理来源，基于强类型的 `DataPort<T>` 作为引脚通信。
* **存储**：底层使用 `TypedBucketMap`。内部**必须使用原生 `Dictionary`** 以追求单线程极限吞吐量，严禁使用 `ConcurrentDictionary`。
* **并发锁机制**：
  * **后台管线摄入**（如 10万级 K 线）：必须使用 `BeginTransaction()` 获取独占写锁。
  * **前台 UI 高频事件**：`WithBoard(...)` 只负责把事件与当前 `DataBlackboard` 绑定，不隐式持有 `UpgradeableReadLock`。读写锁必须在事件处理内部按最小作用域显式获取。

#### 2. 数据流管线 (Workflow / DataPipe)
* **核心铁律**：谁发布，谁执行。
* **`Watch` (同步执行)**：专用于 UI 线程触发的极速 `O(可见数量)` 操作（如视口切片 Viewport Slicing）。**绝不能切线程**，以防画面撕裂。
* **`WatchAsync` (后台线程池)**：专用于耗时的指标计算（如 MACD）。必须遵循 **"Compute-then-Commit"** 模式：瞬间读锁捞数据 -> 裸奔算指标 -> 瞬间写锁提交通知。绝不能在持锁期间进行重度计算。

#### 3. 数据源 (ReactiveDataSource)
* **协议层**：使用 `Task<int> RequestAsync(TRequest, CancellationToken)`，完美桥接 async/await 和响应式流，并返回真实的网络拉取数量。
* **边界真理**：图表左侧推图是否到头（撞墙），**唯一判断标准是服务器回包的数量是否为 0 (`fetchedCount == 0`)**，严禁使用本地黑板的长度做判断。
* **内存防漏**：Token 注册必须严格使用 `await using var registration = token.Register(...)`。

#### 4. 特性层 (ChartFeature)
* **职责分离**：渲染、交互与逻辑必须彻底解耦。Feature 统一通过 `OnCompose` 挂载 workflow / 事件订阅与主 flow 变换，通过 `OnProject` 提交视觉渲染。`OnCompose` 不负责直接返回新的 flow。
* **组件化配置**：交互引擎、视口管家、自动缩放彻底解耦，消除一切魔术数字 (Magic Numbers)，所有容差和边界全量配置化。

## 📜 三、 架构铁律 (The Ironclad Rules)

1. **组件通信绝对隔离**：Feature 必须是“瞎子和聋子”。UI 回调中只能读取和发布 `Trait` 意图，**绝不允许**交互类 Feature 直接触碰底层大数组，更不允许互相持有实例。
2. **Phase 排序机制**：特征执行顺序仅由 `FeaturePhase` 枚举决定（如 `PreLayout` -> `Layout` -> `Scale` -> `Series`）。禁止在 Schema 中通过 `List.Add` 强行控制顺序。
3. **智能重绘拦截**：重型渲染兵必须用 `[Port]` 声明依赖以自动拦截；交互特征必须用 `flow.Watch` 或 `.Subscribe()` 响应流驱动。**严禁**手动 `SetDirty()`。
4. **“三明治”物理树**：底层 Skia -> 中层 WPF Vector -> 顶层 WPF Widget。保持绝对扁平，**严禁**使用 XAML 进行 `Border`/`ScrollViewer` 的嵌套包裹。
5. **动静分离与极值防御**：高频刷新必须采用双图层 + `DataSliceTrait` 分片；所有数值范围判断必须用 `!yRange.IsValid` (校验 Span > 0)，**严禁**只用 `IsEmpty` 拦截导致除零崩溃。
6. **视口纯 Port 驱动**：拖拽交互与数据管线彻底解耦。视口意图传递严禁使用对象分配，全部走强类型引脚 (`UserRange` -> `ActiveRange`)。
7. **比例尺大一统**：物理坐标必须调用 `IScale` 进行 `Normalize`。对齐逻辑 (Offset) 必须封装在 Scale 内部。**严禁**在 Feature 中手写 `(x - min) / span * width` 等物理反推公式。
8. **DataPort 作用域**：框架级约定用 `static readonly`；业务图表端口默认使用实例级 `readonly`，以保证多图表实例间的数据隔离。

9. **Feature 不持有 DataSource**：Feature 是"瞎子和聋子"的延伸——只认 `DataPort<T>` 引脚，**绝不能** `new DataSource<...>()` 或持有 `DataSource` 字段引用。所有数据输入由 Schema 的 `DefineDataFlow` 统一装配管线、写入端口，Feature 只消费 Schema 提供的端口。这条红线保证"一根 K 线画在分时图上"这类组合的前提。

11. **Viewport 自动注入，Axis 显式绑定**（L6 / §B.2.6）：`ChartFeature.Viewport` 由基类 `ReactiveSchema.Add(...)` 自动注入，业务 Feature 直接 `this.Viewport`。扩展方法分层：Series/Interaction/AutoScale 全 0 vp 参数（自动注入）；Axis 族（`AddDomainAxis` / `AddRangeAxis`）保留显式 port 参数（"端口绑定者"语义——X 绑 Viewport、Y 绑 yRangePort 对称）。

12. **IPausable 三级冷冻自动级联**（Phase 11 / §H）：隐藏但未卸载（TabControl 切 Tab、最小化、IsVisibleChanged）由 `ChartCell` 自动触发 `Schema.Suspend/Resume`。Schema 级联 → Feature / DataSource / WorkflowTrigger，再经 `WorkflowEngine.Subscribe` 透传到根源 `Workflow.Interval` 的订阅。业务层**零代码改动**即享受自动冻/解——绝不手动管理 CancellationTokenSource；Schema 级特殊状态（非 IPausable 的外部订阅）通过重载 `OnSuspend / OnResume` 虚钩子处理。

13. **资源链式托管**（Phase 10 / §G）：所有 schema（静态/动态）的 IDisposable 资源（DataSource、TimeAxisCoordinator、内部订阅）通过 `this.Own(new Foo())` 在字段初始化时托管，或 `foo.DisposeWith(this)` 后挂。DynamicSchema 因继承这一能力，不再需要专属 API。

## 四、 业务层装配标准蓝图 (The Schema Blueprint)
所有的装配逻辑必须分为纯净的“管线搭建”与“特征拼装”。使用 C# 9.0+ 的 `init` 属性注入模式。

```csharp
public class XxxSchema : ReactiveSchema
{
    // 实例级端口：确保多图表实例隔离。
    // 注意：Viewport 由基类 ReactiveSchema.Viewport 统一持有（L6 / §B.2.6），
    //      子类不再声明 `private readonly ViewportPorts VP = new();`
    private readonly DataPort<ReadOnlyMemory<double>> PricePort = new("Port_Price");

    protected override IRenderFlow<DataBlackboard> DefineDataFlow(ChartCell chart)
    {
        return _dataSource.Pipe()
            .Inject(ds => ds.Count).ForwardTo(Viewport.LogicalLength)    // 用基类 Viewport
            .End()
            .LinkStream(cfg => cfg.Map(PricePort, x => x.Price, double.NaN))
            .BindTo(chart);
    }

    protected override void DefineFeatures(IFeatureContext context)
    {
        var xAxisMeta = FieldMeta.Literal("时间", Colors.Gray, "HH:mm");

        // 🌍 环境布局域（Series/Environment/Interactions 的 vp 参数已由 Feature 自动注入，无需显式传）
        context.Environment(env => {
            env.SetupLayout(left: ChartLength.Pixel(80))
               .SetupViewport(minVisibleCount: 80);
        })
        // 📏 坐标拓扑域（Axis 族保留显式 Viewport：作为端口绑定者，X 绑 Viewport、Y 绑 yRangePort）
        .Axes(axes => {
            axes.AddDomainAxis(TimePort, Viewport, xAxisMeta);
        })
        // 🕯️ 视觉序列域
        .Series(series => {
            series.AddCandle(YAxisRangePort, CandlePorts);
        })
        // 🖱️ 交互行为域
        .Interactions(interactions => {
            interactions.EnableStandard(TimePort, xAxisMeta, new InteractionOptions<DateTime> {
                Modes = ChartInteractionMode.All, HitPort = HitPort
            });
        });
    }
}
```

## 四-B、多源装配标准蓝图 (Multi-Source Schema)

当业务需要将多路数据源对齐到同一时间轴时，使用 `TimeAxisCoordinator` 替代单源的 `.Pipe().LinkStream(...)` 路径：

```csharp
public class DualCompareSchema : ReactiveSchema
{
    // 💥 规则 #9：业务端口用实例级 readonly，保证多图表实例隔离
    // Viewport 由基类 ReactiveSchema 统一持有（L6 / §B.2.6），子类不再声明
    private readonly DataPort<ReadOnlyMemory<double>> MainPort  = new("Main");
    private readonly DataPort<ReadOnlyMemory<double>> BasePort  = new("Base");
    private readonly DataPort<ReadOnlyMemory<DateTime>> TimePort = new("Time");
    private readonly DataPort<RealRange> YRangePort = new("YRange");

    // 资源通过 this.Own(...) 托管到 Schema 生命周期，随 DecomposeAll 一起 Dispose
    private readonly TimeShareDataSource _mainSource;
    private readonly TimeShareDataSource _baseSource;

    public DualCompareSchema()
    {
        _mainSource = this.Own(new TimeShareDataSource());
        _baseSource = this.Own(new TimeShareDataSource());
    }

    private static double ToPercent(TimeData x, TimeShareDataSource s)
        => s.PreClose == 0 ? double.NaN : (x.Price - s.PreClose) / s.PreClose;

    protected override IRenderFlow<DataBlackboard> DefineDataFlow(ChartCell chart)
    {
        Workflow.FromTask(async _ =>
            await Task.WhenAll(_mainSource.LoadAsync(MainSecurity), _baseSource.LoadAsync(BaseSecurity))
        ).Subscribe(_ => { }, ex => Debug.WriteLine(ex)).DisposeWith(this);

        // N 路对齐：AddSource 任意多次，端口名义绑定，O(L×N) 稳态 0 GC
        var coord = new TimeAxisCoordinator(TimePort);
        coord.AddSource(_mainSource, ToPercent, MainPort);
        coord.AddSource(_baseSource, ToPercent, BasePort);
        return coord.ProjectExtent(Viewport).BindTo(chart);
    }

    protected override void DefineFeatures(IFeatureContext context)
    {
        context.Seed(ScaleStrategyTrait.Default);
        context.Environment(env =>
            env.SetupAutoScale(YRangePort, new[] { MainPort, BasePort },
                strategy: AutoScaleStrategy.SymmetricZero))
        // Axis 保留显式 Viewport（端口绑定者语义）；其他 API 无需 vp
        .Axes(axes =>
            axes.AddDomainAxis(TimePort, Viewport, xMeta)
                .AddRangeAxis(YRangePort, yMeta, AxisPlacement.Left))
        .Series(series =>
            series.AddLine(MainPort, YRangePort, mainMeta)
                  .AddLine(BasePort, YRangePort, baseMeta))
        .Interactions(interactions =>
            interactions.EnableStandard(TimePort, xMeta, new InteractionOptions<DateTime>
            {
                Modes   = ChartInteractionMode.Hover | ChartInteractionMode.Pan,
                HitPort = HitPort
            }));
    }
}
```

> **11 个重复率 ≥ 95% 的双源业务**已沉入 `DualTimeShareSchemaBase` 抽象基类，子类仅需 5 行声明 `MainSecurity` 和 `MainTitle`（见 `Hevo.Drawing/TimeShare/DualTimeShareSchemaBase.cs`）。
