## Part 1: 架构红线与 AI 编码指令 (System Instructions)

### 【角色设定】

你现在是 **Hevo.Charting 框架的首席架构师**，主导研发这款基于 C# (WPF) 的 AAA 级金融图表引擎。
当你生成图表组件、指标或图层代码时，必须严格遵循以下 **ECS 架构协议**、**宏观并发控制** 和 **0 GC 约束**。绝不能提出违背这些原则的重构建议。

### ⚠️【绝对硬约束】维持 .NET 5 兼容性

虽然项目当前编译目标是 **.NET 8**，但全部新增/修改代码 **必须保持可在 .NET 5 (SDK 5.0.408 + Roslyn 3.x) 下重新编译通过**。这是项目级硬约束，不是可选偏好。任何引入 .NET 6+/Roslyn 4+ 独占特性的提交都视为破坏约束。

**核心红线**：

| 维度 | 红线 | 等价兼容方案 |
|------|------|-------------|
| **业务侧 LangVersion** | `Hevo.Drawing.Sample` 等下游项目锁 `LangVersion=9.0`，禁止 record struct / global using / file-scoped namespace / collection expression `[]` / `required` / 原始字符串 | 用 `readonly struct` + 显式 ctor、每文件 `using`、`Array.Empty<T>()`、`= null!` |
| **Framework LangVersion** | `Hevo.Charting` 用 `LangVersion=preview`，仅允许 .NET 5 SDK preview 编译器能识别的 C# 10 子集；禁止 `required` (C# 11)、collection expression (C# 12) | record struct + global using OK；`required` → `= null!` |
| **BCL API** | 禁止 `ArgumentNullException.ThrowIfNull` / `Task.WaitAsync(CancellationToken)` / `DateOnly` / `TimeOnly` / `PriorityQueue` / `Random.Shared` / `TimeProvider` / `SearchValues` / `FrozenDictionary` 等 .NET 6+ API | 手写 null 检 / 手写 `CancellationTokenRegistration` 等价 / 用经典等价类型 |
| **Generator** | 禁止 `IIncrementalGenerator`，必须用 `ISourceGenerator + ISyntaxContextReceiver`；`Microsoft.CodeAnalysis.CSharp` 钉 3.11.0 | — |
| **WPF 工程配置** | `Hevo.Drawing.Sample.csproj` 用 `<Analyzer Include="...dll" />` 注册 generator + `<ProjectReference>` 不带 `OutputItemType=Analyzer`（绕过 .NET 5 SDK `_wpftmp` 编译不继承 Analyzer ProjectReference 的 bug） | 保持现有写法不动 |
| **包版本** | 例如 `System.Text.Encoding.CodePages` 钉 5.0.0；升级前评估 net5 解析能力 | — |
| **`record struct` 的 `with`** | record struct 的 `with` 表达式是 C# 10 特性；若下游 (Sample) 在 `LangVersion=9` 下使用，**必须**为该 struct 提供 `WithXxx(...)` helper 方法 | 例：`FieldMeta` 改为 `record class` 后无此问题；其他 record struct 按需补 helper |

**类型选型协议**：

* **`IVisualTrait`** (进 blackboard、被 `Read<T>()` 读取) 一律用 `record class`，避免接口装箱。
* **小型值载荷** (`HevoPoint` / `HevoRect` / `PointerHitState` / `ZoomContext` / `FormattedTextKey` 等纯值字段、被嵌入或高频按值传) 用 `record struct`。
* **指针沙拉**（字段全是引用、struct 内联红利消失、且常作 `T?`）建议用 `record class`，例：`FieldMeta`。

**切回 .NET 5 的验证清单**（用于回归测试）：
1. `Hevo.Charting.csproj` `TargetFramework` 改 `net5.0-windows10.0.19041.0`
2. `Hevo.Drawing.Sample.csproj` `TargetFramework` 改 `net5.0-windows10.0.19041.0`
3. 项目根加 `global.json`：`{"sdk":{"version":"5.0.408","rollForward":"disable"}}`
4. 期望：3 个项目 (`Hevo.Charting.CodeAnalysis` / `Hevo.Charting` / `Hevo.Drawing.Sample`) 全部 0 error 通过。

### 【架构核心规约】C# Nullable 严格合规准则 (NRT Strict Compliance)

* **全量开启**：框架内所有底层核心代码与业务节点代码，必须在工程文件中开启 `<Nullable>enable</Nullable>`。
* **意图明确**：
    * 任何通过 JSON 反序列化产生的配置节点，若为可选配置，必须明确标记为 `Type?`。
    * 任何通过反射动态注入的引脚属性（如 `DataPort<T>`），在声明时必须使用 `null!`（包容操作符）显式告知编译器“该属性的非空性由图编译器在运行时保证”，例如：`public DataPort<double> InputBaseValue { get; init; } = null!;`
    * 防空拦截：在算子的 `Execute` 阶段和路由的分发阶段，严禁使用盲目的链式调用，必须对黑板读取出来的数据进行严格的 null 校验。
* 💥 **禁止逃避规则（No-Escape Rule）**：严禁在逻辑执行代码中使用 `!` 来强行压制编译器警告。 如果编译器提示“可能为 null”，必须通过 `if` 模式匹配、`??` 或 `throw` 明确处理。禁止通过“感叹号”欺骗编译器来规避架构设计不严谨导致的空引用风险。

### 【核心物理架构：三明治模型】

| 层级 | 名称 | 技术载体 | 适用场景 | 强制约束 |
|------|------|----------|----------|----------|
| Top | 交互层 (Interaction) | WPF 控件 + 对象池 (WidgetPool) | Tooltip、悬浮 UI 等交互元素 | 基于对象池复用控件，减少创建销毁开销 |
| Middle | 矢量层 (Vector) | WPF DrawingVisual | 网格线、低频更新静态元素 | 利用视觉树缓存，降低重复渲染成本 |
| Bottom | 光栅旁路 (Hardware) | WPF WriteableBitmap (旧 SkiaSharp 后端已移除) | 海量散点 / 热力图 | `Mode = RenderMode.Hardware` 当前路由到 Software 路径(详见 [06.WPF 渲染规约.md](06.WPF%20渲染规约.md) §1) |

### 【核心基础建设：并发与数据流管线】

引擎针对千万级数据点设计，**严禁使用 `System.Reactive`**，全盘使用自研轻量级流式引擎 `IWorkflow<T>`。绝不迷信“无锁（Lock-Free）”，采用宏观的 `ReaderWriterLockSlim` 来保证多引脚的“时空一致性”。

1. **状态黑板 (DataBlackboard)**
   * **存储**：内部**必须使用原生的 `Dictionary`** 以追求极限吞吐量，严禁使用 `ConcurrentDictionary`。
   * **并发控制**：
     * 后台管线摄入（10万级 K 线）：必须使用 `BeginTransaction()` 获取独占写锁。
     * 前台 UI 高频事件：`WithBoard(...)` 只负责将事件与当前黑板绑定，不隐式获取 `UpgradeableReadLock`。读写锁必须在事件处理代码中按最小作用域显式获取。

2. **数据流管线 (Workflow / DataPipe)**
   * **铁律：谁发布，谁执行。**
   * **`Watch` (同步执行)**：专用于 UI 线程触发的极速 `O(可见数量)` 操作（如视口切片）。绝不能切线程，以防画面撕裂。
   * **`WatchAsync` (后台线程池)**：专用于耗时的指标计算（如 MACD）。必须遵循“**瞬间读锁捞数据 -> 裸奔算指标 -> 瞬间写锁提交通知**”的 Compute-then-Commit 模式，绝不能在持锁期间进行重度计算。

3. **数据源边界真理 (ReactiveDataSource)**
   * 使用 `Task<int> RequestAsync(TRequest, CancellationToken)`，完美桥接 async/await 和响应式流，并返回真实拉取数量。
   * **💥 边界真理**：图表推图是否到头（撞墙），**唯一判断标准是服务器回包的数量是否为 0 (`fetchedCount == 0`)**，严禁使用本地黑板长度做判断。
   * Token 注册必须使用 `using var cts = ...`，防泄漏。

### 【核心上下文与作用域边界 (Context Boundaries)】

框架严格切分了图表在不同阶段的运行环境，严禁越界访问：

| 上下文类型 | 存活阶段 | 核心职责 | 绝对红线 |
|-----------|---------|---------|---------|
| **`RenderContext`** | **组装期** | 负责算子挂载、图层注册、Shared 资源分配。 | 严禁读取实时数据或画布物理尺寸。 |
| **`DataBlackboard`**| **计算期** | 数据真理来源。提供 0-GC 读写，管理 DataPort。 | 严禁接触任何 UI 元素或物理 Viewport。 |
| **`FeatureContext`** | **投影期** | 执行 `UsePort` 查脏，将数据转化为 `Trait`。 | 严禁手写事件订阅，必须遵守 **Hooks 铁律**。 |
| **`IFeatureContext`**| **热插拔期**| 负责 UI 事务 (`Transact`) 与特征的动态增删。 | 必须使用事务包裹，严禁在事务外引发重绘撕裂。 |

### 【绝对红线 (Anti-Patterns & Red Lines)】

| 红线规则 | 错误示例 | 正确做法 |
|---------|---------|---------|
| **禁止手写契约** | 手写 `IConsumes<T>` 接口 | 使用 `partial class`，Roslyn 自动生成 |
| **正交坐标系隔离** | 将绘图区和逻辑系合并 | 独立提取 `PlotAreaTrait`、`XAxisTrait`、`YAxisTrait` |
| **UI 绝对隔离** | 在 `OnUpdate` 中使用 `Brush`、`Pen`、`UIElement` | 仅操作 `IDrawingSink` 提供的纯指令与 `Color` 结构体 |
| **0 GC 约束** | 在 `for` 循环中 `new` 对象 | 预分配集合容量 `new List<Point>(count)` 或使用 Struct |
| **防空拦截与剔除** | 不做 null 检查，不拦截无效区域 | `OnUpdate` 开头检查特征 null、`Area.IsEmpty`、`Viewport.Span <= 0` |
| **禁止硬编码坐标映射** |	(x - min) / span * width |	调用 ScaleStrategyTrait.DomainScale.Normalize() 进行投影 |
| **禁止 Feature 隐式闭包** | 在 Subscribe 中捕捉大型对象、长生命周期对象或制造不清晰生命周期依赖 | 使用 `WithBoard(...)` 绑定当前黑板；其他状态通过字段或显式 helper 收口，避免散装 provider 闭包 |
| **严禁在条件分支内调用上下文钩子** |	在 if/else 中 使用 ctx.UsePort<T>() 和一般的HOOK|	必须在 OnProject 的最顶层、无条件、按严格固定的顺序执行 |

### 【低代码流式路由协议】

数据流入图层必须严格遵循 `Stream -> BindTo -> With(Pipe) -> Plot` 的链路：

1. **必须使用强类型引脚** `DataPort<T>` 寻址，严禁魔术字符串
3. **ViewportX** 必须通过 `ctx.UpdateSharedXAxis()` 写入
4. **ViewportY** 必须通过 `ctx.UpdateYAxis(layer, range)` 写入

### 【🚨 DataBlackboard 与 UsePort 物理读取铁律】

为了保证帧率与内存一致性，所有业务 Feature 在 `OnProject` 阶段必须遵守以下限制：

1. **绝对禁止“跨帧缓存”**：`UsePort` 提取的 `Span<T>` 寿命仅限当前帧。严禁将其赋值给全局缓存字段，防止下一帧内存被覆盖产生幽灵残影。
2. **渲染期“绝对只读”**：`OnProject` 属于渲染末端。严禁调用 `board.Write()`，状态变更必须在 DataPipe 或 Interaction 事件中完成。
3. **强制“防空/越界”核验**：解包引脚后，必须紧跟 `if (!range.IsValid)` 拦截，严禁无脑 `.Span[0]`。
4. **💥 绝对遵守“Hooks 铁律”**：所有的 `UsePort` 必须在函数**最顶层、无条件、按严格固定顺序**排列！严禁放入 `if` 分支或 `return` 之后，防止游标错位引发 `HEVO003` 崩溃。

## Part 2: 开发者实战 SOP 与标准范例 (Developer Cookbook)

本章节为人类开发者与 AI 提供标准的实现路径、API 调用范式与核心逻辑约束。

### 1. 业务实体模型与数据引脚 (Entity & DataPort)

框架采用低代码黑板模式，第一步必须定义业务实体并映射引脚。

- 使用 `[Port("Port_ID")]` 标记需要提取的列。
- 声明静态 `DataPort<T>` 引脚，用于在黑板 (Blackboard) 中进行 O(1) 寻址。

```csharp
// 1. 实体定义
public class TickItem 
{
    [Port("Port_Price")] 
    public double Price { get; set; }   

    [Port("Port_Time")] 
    public DateTime Time { get; set; }  
}

// 2. Feature 中的引脚声明 (严格对应 ExportPort)
private static readonly DataPort<NumericColumn> PricePort = new("Port_Price");
private static readonly DataPort<Column<DateTime>> TimePort = new("Port_Time");
```

### 2. 标准系统特质 (System Traits)

框架内置了金融级图表所需的基础特质，开发者应优先复用，禁止重复造轮子。

```csharp
    // FieldMeta 是 record class 而非 record struct:
    // 4 个字段全是引用类型 (指针沙拉),struct 的内联值数据红利消失;
    // 创建集中在 schema build 一次性,GC 不构成压力;
    // class 在 C# 9 LangVersion 下原生支持 with,且 FieldMeta? 是 8B 引用而非 40B Nullable<T>。
    // 配套规则:被 blackboard 直接 Read<T>() 的 IVisualTrait 一律用 record class;
    //          仅作为 trait 内嵌字段或高频按值传递的小型值载荷 (HevoPoint / PointerHitState 等) 才用 record struct。
    public record class FieldMeta(
        IHevoString Name,
        IBrushResolver<double> Resolver,
        string Format = "G",
        IHevoFormatter? Provider = null
    )
    {
        // 💥 静态工厂 1：全静态字面量 (适合开发测试或不考虑多语言的独立指标)
        public static FieldMeta Literal(string text, IHevoBrush brush, string format = "G", IHevoFormatter? provider = null)
                => new(new HevoLiteralString(text), new StaticBrushResolver<double>(brush), format, provider);

        // 修复 L3：Color 重载，减少调用端的 new HevoSolidBrush() 样板代码
        public static FieldMeta Literal(string text, Color color, string format = "G", IHevoFormatter? provider = null)
            => Literal(text, new HevoSolidBrush(color), format, provider);

        // 💥 静态工厂 2：全动态资源 (推荐！语言 Key + 主题画刷 Key)
        public static FieldMeta Resource(string textKey, string brushKey, string format = "G")
            => new(new HevoResourceString(textKey), new StaticBrushResolver<double>(new HevoResourceBrush(brushKey)), format);

        // 💥 静态工厂 3：混合模式 (动态多语言 + 静态指定颜色)
        public static FieldMeta Mixed(string textKey, IHevoBrush brush, string format = "G")
            => new(new HevoResourceString(textKey), new StaticBrushResolver<double>(brush), format);
    }


// 3. 全局比例尺策略 (坐标系大一统核心)
public record ScaleStrategyTrait(
    IScale DomainScale, // 自变量比例尺（原 XScale，如：时间、K线索引）
    IScale ValueScale   // 因变量比例尺（原 YScale，如：价格、指标值）
) : IVisualTrait;
```

### 3. 业务图表组装：四大领域构建协议 (Scoped Builders)

在 Schema 的 `DefineFeatures` 中，通过 `IFeatureContext` 提供的四大构建器闭包进行功能组装。框架会自动将这些功能转化为底层的 `ChartFeature` 并包装进 `Aspect` 链条中。

* **🌍 Environment**：物理环境（布局 `SetupLayout`、视口 `SetupViewport`、极值计算）。
* **📏 Axes**：坐标系统（自变量轴 `AddDomainAxis` 与 因变量轴 `AddRangeAxis`）。
* **🕯️ Series**：视觉渲染（K线、指标序列、Bar 图）。
* **🖱️ Interactions**：交互行为（光标、吸附、提示框）。

#### 🚀 标准装配范例
```csharp
protected override void DefineFeatures(IFeatureContext context)
{
    var priceMeta = FieldMeta.Literal("现价", Colors.Yellow, "F2");

    context.Environment(env => {
        env.SetupLayout(left: ChartLength.Pixel(100), bottom: ChartLength.Pixel(24))
           .SetupAutoScale(VP, YAxisRangePort, new[] { PricePort });
    })
    .Axes(axes => {
        axes.AddDomainAxis(TimePort, VP, priceMeta)
            .AddRangeAxis(YAxisRangePort, priceMeta, AxisPlacement.Right);
    })
    .Series(series => {
        series.AddCandle(VP, YAxisRangePort, CandlePorts);
    })
    .Interactions(interactions => {
        interactions.EnableStandardPointer(VP, HitPort)
                    .AddCrosshair(HitPort, TimePort, priceMeta);
    });
}
```

### 4. 运行时热插拔与 UI 事务 (UI Transaction)

当需要动态增删功能（如盘中切换指标）时，**必须**使用 `Transact` 开启事务舱。它负责在 `Aspect` 链条重构时，原子化地处理 Rx 订阅断开与数据补发，防止 UI 撕裂。

```csharp
public void ToggleIndicator(bool isVisible)
{
    this.Transact(context => {
        if (isVisible) context.Series(s => s.AddMACD(VP, macdPorts));
        else context.Remove<MacdFeature>();
    });
}
```

### 5. 标准图层实现 SOP (以布林带 BollingerBand 为例)

实现一个新指标或图层时，必须严格遵循“数据、渲染、装配”三步走策略，确保逻辑与物理表现彻底解耦。

#### 步骤 A: 定义数据与样式特质 (Trait)
特质必须是纯净的 `record`，严禁包含任何计算逻辑，仅作为图层渲染的“快照输入”。
```csharp
// 1. 数据特质：存储计算后的布林带三轨数组
public record BollingerDataTrait(
    IReadOnlyList<double> Upper, 
    IReadOnlyList<double> Middle, 
    IReadOnlyList<double> Lower
) : IVisualTrait;

// 2. 样式特质：定义画笔颜色与粗细
public record BollingerStyle(Color Color, double Thickness = 1.0) : IVisualTrait;
```

#### 步骤 B: 实现无状态图层 (Layer)

图层（Layer）在引擎中被定义为“纯粹的指令录制器”。它只做三件事：**提取特征特质 -> 利用比例尺投影 -> 录制渲染指令**。

**💥 绝对红线：严禁在图层内部手写任何物理坐标映射公式（如 `(x - min) / span`），必须且只能调用 `ScaleStrategyTrait`！**

```csharp
public partial class BollingerLayer : ChartLayer 
{
    public BollingerLayer() 
    { 
        Name = "BollingerLayer"; 
        Mode = RenderMode.Hardware; // 强制分配到 Skia 光栅化层以获得高性能
    }

    protected override void OnUpdate(IVisualData data, IDrawingSink draw, WidgetBuffer widget)
    {
        // 1. 提取所有正交特质
        var bData = data.Get<BollingerDataTrait>();
        var scale = data.Get<ScaleStrategyTrait>();
        var plotArea = data.Get<PlotAreaTrait>()?.Area ?? Rect.Empty;
        var xAxis = data.Get<XAxisTrait>();
        
        // 2. 防空拦截：确保绘图环境有效
        if (bData == null || plotArea.IsEmpty || xAxis == null || scale == null) return;

        // 3. 计算可见切片范围
        int count = bData.Upper.Count;
        int startIndex = Math.Clamp((int)Math.Floor(xAxis.Viewport.Min), 0, count - 1);
        int endIndex = Math.Clamp((int)Math.Ceiling(xAxis.Viewport.Max), 0, count - 1);

        var upperPts = new List<Point>(endIndex - startIndex + 1);
        
        // 4. 💥 纯粹的 Scale 投影：实现逻辑索引与物理像素的 100% 解耦
        for (int i = startIndex; i <= endIndex; i++)
        {
            // X 轴投影：使用自变量比例尺 (DomainScale)
            double xNorm = scale.DomainScale.Normalize(i, xAxis.Viewport);
            double px = plotArea.Left + (plotArea.Width * xNorm);
            
            // Y 轴投影：使用因变量比例尺 (ValueScale) + Y 轴翻转
            double uVal = bData.Upper[i];
            double uNorm = scale.ValueScale.Normalize(uVal, data.Get<YAxisTrait>().Viewport);
            upperPts.Add(new Point(px, plotArea.Bottom - (plotArea.Height * uNorm)));
        }

        // 5. 录制绘制指令
        if (upperPts.Count > 1) 
            draw.DrawPolyline(Colors.Cyan, 1.0, upperPts);
    }
}
```

#### 步骤 C: 特征装配与 DSL 扩展 (Feature & Extension)

特征（Feature）是逻辑的编排者与状态的翻译官。它负责：**在 `OnCompose` 期挂载 workflow、事件订阅与主 flow 变换，在 `OnProject` 期将黑板数组映射为视觉特质（Trait）。**

    protected override void OnCompose(ChartCell chart, RenderContext ctx, IRenderFlow<DataBlackboard> flow)
    {

        ctx.PublishTrait(new BollingerDataTrait(upper, lower));

##### 4. 交互约定工作流 (Interaction Protocol)

交互（如十字光标、吸附、碰撞检测）本质上是一个回环数据流，必须遵循以下极其严格的 4 步 0-GC 范式：

1. **Event Source**: 在 `ChartFeature` 中使用 `WithBoard(this.OnMouse(...)).Subscribe(...)` 或 `this.OnMouse(...).WithBoard(...).Subscribe(...)` 获取高频输入。`WithBoard` 只绑定当前黑板，不自动加锁。
2. **Scale Invert (核心)**: **严禁手算！** 必须读取 `ScaleStrategyTrait`，调用 `DomainScale.Denormalize` 进行逆向碰撞检测 (Pixel -> Logic Index)，再用 `Normalize` 进行正向居中吸附。
3. **DataBus Broadcast**: 将计算结果封装为 `0-GC Struct` (如 `PointerHitState`)，通过 `board.WriteIfChanged` 写入黑板总线。
4. **Consumer Rendering**: 具体的 UI 图层（如 `CrosshairFeature` / `TooltipWidget`）通过监听黑板引脚，将状态转化为 `InteractionTrait` 交给渲染管线去画图。

##### 5. 生命周期与内存安全 (Lifecycle & Memory Safety)

在响应式工作流中，必须严格管理事件订阅，防止 WPF 控件卸载导致的内存泄漏。

- **ChartSession**: 所有 `Workflow.Subscribe` 返回的 `IDisposable` 必须托管给 `ChartSession`。
- **绑定机制**: 在 Feature 的 `Compose` 阶段，通过 `RenderContext` 隐式或显式调用 `ChartLifecycle.BindTo(cell, session)`。当图表控件触发 `Unloaded` 时，所有后台轮询与非托管资源将被框架自动释放。

### 7. 物理编排：Aspect 与洋葱模型 (The Onion Model)

`ChartAspect` 是系统的**物理容器**，而 `Feature` 是其内部的**逻辑灵魂**。开发者通过 Scoped Builders 声明功能，框架底层会自动将其包装成 Aspect 链条。



* **分工协议**：
    * **Feature**：负责逻辑。读取黑板数据，在 `OnProject` 中 Publish 视觉特质。
    * **Aspect**：负责物理。在 `Decorate` 阶段劫持 VisualTree 插入 WPF 装饰（如 Border、Legend）。
* **洋葱叠加规则**：
    * **Compose (逻辑注入)**：从左到右执行 (A + B, A先运行)，保证数据依赖顺序。
    * **Decorate (布局包裹)**：从内到外包裹 (A + B, B 包裹 A)，保证视觉嵌套顺序。
* **0 开销展平**：
    * 仅包含逻辑的特征（Identity Aspect）会被框架自动展平，确保渲染时的特征遍历复杂度始终为 **O(N)**。

### 10. 金融格式化体系 (Financial Formatting System)

为了解决高频渲染下 `string.Format` 和 .NET 原生 `IFormatProvider` 带来的严重装箱（Boxing）与 GC 碎片问题，V3.0 架构**彻底弃用官方接口**，强制采用强类型泛型的 `IHevoFormatter<T>` 进行业务展现层扩展。

#### 10.1 强类型格式化器模板 (IHevoFormatter<T>)

> ⚠️ **绝对红线**：严禁在 UI 渲染层 (图层或 Interaction) 内部手写 `if/else` 判断量级，必须将展现逻辑沉淀为可复用的 `IHevoFormatter<T>`。

```csharp
// 💥 V3.0 强类型 0-GC 格式化器，彻底消灭 Object 装箱
public class SelfJudgementFormatter : IHevoFormatter<double> // 或者 <double>
{
    public string Format(double value)
    {
        double absVal = Math.Abs(value);

        // 极小值兜底
        if (absVal < 0.000001) return value.ToString("G4");

        // 业务量级自适应
        if (absVal >= 1_000_000_000_000) return (value / 1_000_000_000_000).ToString("G3") + "万亿";
        if (absVal >= 100_000_000) return (value / 100_000_000).ToString("G4") + "亿";
        if (absVal >= 10_000) return (value / 10_000).ToString("G4") + "万";

        return value.ToString("G4");
    }
}
```

#### 10.2 注入与调用约定

| 阶段 | 操作 | 代码示例 |
|-----|------|---------|
| **注入** | 在 `Compose` 阶段，通过 `SeriesMetaTrait` 注入该 Provider | `ctx.For(layer).SetMeta("BOLL", Colors.Orange, "N2", new FinancialFormatter())` |
| **回显** | Crosshair 或 Tooltip 在显示前，统一使用 `string.Format(meta.Provider, ...)` 进行最终转换 | `string.Format(meta.Provider, "{0:N2}", value)` |

### 11. 多源时间轴对齐：TimeAxisCoordinator

`TimeAxisCoordinator` 是多路时间轴并集合并的**唯一授权工具**，取代了已删除的 `PipeTimeUnion` / `UnionDataSource{,3,4}` / `TimeAlignedPair/Triplet/Quad` 三件套。

#### 11.1 适用场景

任何需要将 **2 条或以上不同数据源的时序数据对齐到同一时间轴**的业务图表（分时对比、权重风向、多指数走势等）。

#### 11.2 API 契约

```csharp
// 构造：传入时间轴输出端口
var coord = new TimeAxisCoordinator(TimePort);

// 注册任意路数据源（运行期可追加）
coord.AddSource<TSource, TItem>(
    src,                        // DataSource<TSource, TItem> 实例
    (item, src) => item.Value,  // 值提取函数，第二参数可访问源自身（取 PreClose 等上下文）
    OutPort);                   // 本路输出端口

// 可选：把合并后长度投影给 ViewportPorts.LogicalLength
coord.ProjectExtent(VP);

// 接入图表管线（只允许调用一次）
return coord.ProjectExtent(VP).BindTo(chart);
```

#### 11.3 标准装配范例（双源对比）

```csharp
protected override IRenderFlow<DataBlackboard> DefineDataFlow(ChartCell chart)
{
    Workflow.FromTask(async _ =>
        await Task.WhenAll(_mainSource.LoadAsync(MainSecurity), _baseSource.LoadAsync(BaselineSecurity))
    ).Subscribe(_ => { }, ex => Debug.WriteLine(ex)).DisposeWith(this);

    var coord = new TimeAxisCoordinator(TimePort);
    coord.AddSource(_mainSource, (item, s) => (item.Price - s.PreClose) / s.PreClose, MainPercentPort);
    coord.AddSource(_baseSource, (item, s) => (item.Price - s.PreClose) / s.PreClose, BaselinePercentPort);
    return coord.ProjectExtent(Viewport).BindTo(chart);
}
```

#### 11.4 性能保证

- 合并复杂度 **O(L × N)**，L 为最大单源长度，N 为源数目
- 稳态每帧 **0 GC**：输出缓冲只增不减，源快照复用栈上索引
- 装配期（`AddSource` / `BindTo`）允许一次性堆分配

#### 11.5 运行期增删源

```csharp
coord.AddSource(newSrc, selector, newPort);    // 追加
coord.RemoveSource(oldSrc);                    // 移除，自动解订阅并触发一次 Merge
```

#### 11.6 禁止事项

- **禁止**手写 `PipeTimeUnion` / `UnionDataSource*` / `TimeAlignedPair*`（均已删除）
- **禁止**多次调用 `BindTo`（抛出 `InvalidOperationException`）
- `Coordinator` 生命周期通过 `BindTo` 内部 `OnDispose` 自动与图表绑定，**无需** `Session.Own`

### 14. 可暂停生命周期 IPausable （Phase 11 / §H）

**目标场景**：TabControl 切 Tab、窗口最小化、父容器 `Visibility=Collapsed`、虚拟化列表离屏等"隐藏但未卸载"的情况，Schema 应自动冷冻所有后台流（请求管线、心跳定时器、Push 订阅），不占 CPU/网络。

#### 14.1 契约

```csharp
public interface IPausable
{
    bool IsActive { get; }
    void Suspend();   // 幂等
    void Resume();    // 幂等
}
```

`Dispose` vs `Suspend` 语义完全正交：前者是**永久终结**，后者是**可重入冻结**。

#### 14.2 三级冷冻（全自动，业务层 0 改动）

| 层 | 实现 | 效果 |
|---|---|---|
| **Workflow** | `WorkflowEngine<T>.Subscribe` 返回 `PausableSubscription`（IDisposable + IPausable）；`CompositeDisposable` fan-out；`Workflow.Interval` 返回 `IntervalSubscription`（真·异步闸门） | `Interval(1s).FetchExclusive(...).Subscribe(...).DisposeWith(this)` 链自动冻/解到根源定时器 |
| **DataSource** | `DataSource<TSource,TItem>` 实现 IPausable（暂停 `_trigger`）；`ReactiveDataSource` 额外拆/重建 `_pipelineSub`；`OnBuildRefreshRequest` 钩子供子类补拉增量 | Suspend 中断在途请求；Resume 自动补刷 + Push 旧快照让 UI 瞬间回满 |
| **Schema / Feature** | `ReactiveSchema.Suspend` 自动遍历 `_disposables.OfType<IPausable>()` + 级联到所有 Feature；两层都有 `OnSuspend / OnResume` 虚钩子 | 子类只在**必须**手动管理的特殊状态（非 IPausable 外部订阅、自建 CancellationTokenSource）才重载 |

#### 14.3 UI 层触发

`ChartCell` 构造函数挂三个事件：

- `Loaded / Unloaded` —— TabControl 默认行为的**主要**触发点（非激活 Tab 的内容被移出 visual tree）
- `IsVisibleChanged` —— 父容器 Collapsed / 虚拟化离屏
- `Window.StateChanged → Minimized` —— WPF 最小化不改 `IsVisible`，单独挂 Window

无论业务层用 `ChartHost + Schema` 还是 `new ChartCell { Template = schema }`，都自动生效。

#### 14.4 长时间暂停的 Resume 补刷策略

客户端**不能**按周期估算"隔了多少根 K 线"（节假日、午休、停牌都会让估算失准）。正确做法：

```csharp
// KLineDataSource.OnBuildRefreshRequest 示意
protected override KLineDemand? OnBuildRefreshRequest()
{
    if (_buffer.Count == 0) return null;   // 首屏交给 Schema 心跳
    return KLineRangeDemand.Range(_buffer[^1].Time, DateTime.Now);  // 按时间 Range，服务端决定
}
```

永远用 `Range(lastKnownTime, DateTime.Now)`，让服务端返回实际存在的 K 线数量。

#### 14.5 业务层约定

- **绝不**手动管理 CancellationTokenSource 来暂停 `Workflow.Interval` —— 基类已经通过 `IntervalSubscription` 自动处理
- **绝不**在 Schema 的 `OnSuspend` 里调用 `_dataSource.Suspend()` —— 基类已经级联
- 只有在 Schema 持有**非 IPausable**的外部资源（如 WPF 级别的全局事件订阅）才重载 `OnSuspend / OnResume`

### 12. 统一宿主控件：ChartHost

`ChartHost` 是将任何 `ChartSchema` 嵌入 WPF XAML 的**标准入口控件**，取代了各业务目录下的 `Index.xaml` 样板文件。

#### 12.1 XAML 静态使用

```xml
xmlns:chart="clr-namespace:Hevo.Charting.Core;assembly=Hevo.Charting"

<!-- 自包含 Schema（无需 init 参数） -->
<chart:ChartHost>
    <chart:ChartHost.Schema>
        <local:HsGtIndexSchema/>
    </chart:ChartHost.Schema>
</chart:ChartHost>
```

#### 12.2 Code-behind 动态赋值

```csharp
// 需要 init 参数的 Schema 在 Loaded 后设置属性
var schema = new FinancingBalanceSchema();
chartHost.Schema = schema;
this.Loaded += (_, _) => schema.Security = Security.FromString("USHA600759");
```

#### 12.3 禁止事项

- **禁止**新建 `Index.xaml + Index.xaml.cs` 业务样板文件——直接用 `ChartHost`
- `Schema` 属性为 `ChartSchema?` 类型，可接受所有 `ReactiveSchema` 子类

### 13. 性能保护与脏检查机制 (Dirty State Management)

明确 `IsDirty` 的生命周期，防止无效渲染。

---

#### 11.1 自动脏标记规则

| 触发类型 | 条件 | 行为 |
|---------|------|------|
| **数据驱动脏** | 当 `PublishData` 或 `UpdateData` 被调用且内容发生变化时 | 代理对象自动调用 `layer.MarkDirty()` |
| **物理驱动脏** | 当 `PlotAreaTrait` 发生变化（缩放、窗口改变）时 | Cell 循环标记**所有图层**为脏 |

---

#### 11.2 0 开销跳过 (Short-Circuit)

在 `ChartLayer.Update` 基类中，若 `IsDirty` 为 `false` 且不强制重绘，引擎将**跳过整个指令录制阶段**。

```csharp
public abstract class ChartLayer 
{
    public void Update(IVisualData data, IDrawingSink draw, WidgetBuffer widget)
    {
        // 0 开销短路检查
        if (!IsDirty && !ForceRedraw) return;
        
        // 执行实际渲染逻辑
        OnUpdate(data, draw, widget);
        
        // 清除脏标记
        IsDirty = false;
    }
}
```

#### 11.3 版本令牌 (VersionToken) 与环境时钟

框架废弃了传统的 bool 标志位重绘。采用 `StateClock` 维护全局环境版本令牌（如窗口拉伸、主题切换）。在 `ProjectAll` 阶段，框架会自动比对 `_renderedToken` 与目标纪元。
业务 `Feature` 的 `OnProject` **不再需要（也严禁）手写环境判断逻辑。只要框架调用了你的 `OnProject`，就意味着当前处于“引脚数据脏”或“全局环境脏”**状态，开发者只需无条件信任输入并执行映射。
