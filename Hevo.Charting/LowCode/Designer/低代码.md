# Hevo 蓝图编译器 (Blueprint Compiler) 架构准则

## 1. 业务降维与性能升维的矛盾
* **现象：** 图形引擎为了达成 60FPS 的百万级渲染，必须针对特定的业务流（如 A股分时图 240 点）采用极其极端的预分配数组占位策略 (`BindIndexedColumn`)。
* **危机：** 绝不能让这种底层优化的要求，反向污染最终用户的 Blueprint (蓝图 JSON)，否则将严重增加低代码平台的心智负担；同样，也绝不能让领域层的 `DataSource` 感知到数组和内存的存在。

## 2. 核心架构解药：ComponentMetadataRegistry (元数据注册表)
* **定义：** 我们在 `Compiler` 引擎内部引入了**“透明优化代理”**机制。它是一个全局的静态字典。
* **如何工作：** 当 `BlueprintCompiler` 发现用户使用了某个特定的 `DataSource` (例如 `"TimeShareDataSource"`) 时，编译器会去注册表查询：“针对这个数据源，有没有更暴力的底层内存映射策略？”
* **结果：** 注册表返回一个闭包，接管该引脚的管线装配。用户在蓝图中配置的明明只是一个普通的属性，底层管线却悄悄为它生成了一个自带时间轴映射的、绝对 0-GC 的 240 长度 `ReadOnlyMemory<double>`。

## 3. 开发戒律 (Coding Commandment)
* **禁止在蓝图模型中暴露性能配置：** 任何新增的算子 (ComputeNode) 或数据源 (DataSource)，如果涉及到特殊的数组排列（比如必须要求连续的块内存），禁止在 `Blueprint` 的 JSON Schema 里加类似 `IsFixedLength` 的参数。
* **必须在 Registry 中登记：** 你必须前往 `ComponentMetadataRegistry`，为你的数据源类型手动注册一个管线编译策略。保持蓝图模型的纯洁，是一切组合扩展的底线。
