# 低代码蓝图设计

> 由 JSON 蓝图在运行时动态孵化 `ReactiveSchema` 的能力。
> 实现位于 `Hevo.Charting/LowCode/Designer/`,由 `ChartBlueprint` + `DynamicChartSchema<T>` + `ComponentRegistry` + `SmartActivator` + `ComponentMetadataRegistry` + `BlueprintRunner` 六件套构成。
>
> **工程改造计划**见 [低代码优化方案.md](低代码优化方案.md):反射热路径缓存、类型冲突早期诊断、单例污染兜底、JsonConverter schema 稳定化等带优先级的落地清单(§1–§10 已交付)。
> **JSON 序列化标准入口**:[BlueprintJsonOptions.Default](Converters/BlueprintJsonOptions.cs) ——
> 蓝图持久化要走这份 options(注册了 Color / IHevoBrush 多态 Converter + NaN/Infinity 数字策略),
> 别每个调用点 new 一份新的,否则 schema 不对齐 → round-trip 出问题。

## 1. 蓝图模型(JSON Schema)

`ChartBlueprint` 的运行态结构(见 [ChartBlueprint.cs](ChartBlueprint.cs)):

```jsonc
{
  // 1. 数据源:类型名 + 字段→引脚 ID 的映射
  "DataSource": {
    "TypeName": "TimeShareDataSource",
    "ScalarMappings": {                  // 标量字段(单值上下文,从 DataSource 实例上反射取值)
      "PreClose": "Env_PreClose"
    },
    "VectorMappings": {                  // 向量字段(从 TItem 上反射取列,自动包成 ReadOnlyMemory<T>)
      "Time":  "RealTime_Time",
      "Price": "RealTime_Price"
    }
  },

  // 2. 初始 Trait 播种:Schema 启动时一次性 Seed 进 Shared 域
  "InitialTraits": [
    {
      "TraitTypeName": "ScaleStrategyTrait",
      "Preset": "Default"                // 直接拿 ScaleStrategyTrait.Default 静态字段
    }
  ],

  // 3. Features 装配清单:运行时反射创建并 Add 到 canvas
  "Features": [
    {
      "TypeName": "PlotAreaDecorFeature",
      "Properties": { /* 普通可写属性 */ },
      "PortBindings": { /* Feature 上 DataPort<T> 字段 → 全局引脚 ID */ }
    },
    {
      "TypeName": "LineSeriesFeature",
      "Properties": { "LayerName": "TrendLine" },
      "PortBindings": {
        "DataPort":   "RealTime_Price",
        "YRangePort": "Final_Y_Range"
      }
    }
  ]
}
```

> ⚠️ 历史上曾设计过 `Layers` / `ComputeNodes` / `Sinks` 三段式蓝图,代码已演进为**只有 Features**(见 [ChartBlueprint.cs:11](ChartBlueprint.cs:11) 注释)。文档与代码同口径。

## 2. 装配引擎

```csharp
// 业务侧一行启动
var ds = new TimeShareDataSource();
BlueprintRunner.Run<TimeData>(host.Cell, blueprint, ds, ds.Stream);
// 等价快捷重载(自动接 ds.Stream)
BlueprintRunner.Run(host.Cell, blueprint, ds);
```

`BlueprintRunner` 内部:

```csharp
var schema = new DynamicChartSchema<TItem>(blueprint, dataSource, stream);
chart.Template = schema; // 由 ChartCell 接管 schema 生命周期
```

`DynamicChartSchema<T>` 三件事(见 [ChartBlueprint.cs](ChartBlueprint.cs)):

1. **`DefineDataFlow`**
   - 优先查 [`ComponentMetadataRegistry`](ComponentMetadataRegistry.cs):若数据源类型登记了自定义策略,整支管线交由策略接管。
   - 否则按 `DataSource.ScalarMappings` 反射构造 `ContextIngestor<TItem,TSource,TValue>`、按 `VectorMappings` 反射构造 `ScatterIngestor<TItem,TValue>`。
   - 用 `StartWith(ds.GetSnapshot())` 灌首帧,`DoOnDispose(pipe.Dispose)` 收尾,最后 `.BindTo(chart)` 注册主流。
   - 数据源若实现 `IDisposable` / `IPausable`,会自动通过 `RegisterDisposable` 挂在 schema 生命周期上,无需业务 `OwnedBy(this)`。
2. **`DefineFeatures`** — 遍历 `InitialTraits` Seed,遍历 `Features`:
   - `ComponentRegistry.Resolve(TypeName)` 拿 Type
   - `Activator.CreateInstance` 实例化 (要求 Feature 有 public 无参 ctor;有参的需走自定义注册或 `IPipelinePolicy`)
   - `SmartActivator.InjectProperties` 注 Properties
   - `PortBindings` 把全局引脚焊到 Feature 的 `DataPort<T>` 字段(init-only 字段反射 SetValue 直接穿透)
   - `canvas.Add(feature)`
3. **全局引脚注册表** — 同一个 `portId` 在该 Schema 内全局唯一,跨 Feature 共享 `DataPort<T>` 实例。

## 3. 组件注册

### 手动登记
```csharp
// 应用启动时注册可用类型,Resolve 时按 TypeName 字符串查表
ComponentRegistry.Register<LineSeriesFeature>();
ComponentRegistry.Register<TimeShareDataSource>();
ComponentRegistry.Register<ScaleStrategyTrait>();
```

### 反射批量登记(推荐)
```csharp
// 自动收录 Hevo.Charting 自带的 ChartFeature / IVisualTrait / DataSource
BuiltinRegistration.RegisterBuiltins();

// 顺手把业务程序集也扫一遍 (TimeShareDataSource 等)
BuiltinRegistration.RegisterAssemblyOf<TimeShareDataSource>();
```

收录条件(详见 [BuiltinRegistration.cs](BuiltinRegistration.cs)):
- ChartFeature:public、非抽象、非泛型定义、有 public 无参 ctor (例:`AxisFeature` 因 ctor 需 `ITickProvider` 不会被自动登记,如需暴露给蓝图,业务侧自行 wrap 一个无参派生类)。
- IVisualTrait:public、非抽象、非泛型定义。无参 ctor 不强制 (record 走 Preset)。
- DataSource:沿继承链找 `DataSource<,>`。

未注册的 `TypeName` 在 Resolve 时直接抛"未知组件类型"异常,蓝图加载即失败。

## 4. 性能优化代理(透明优化)

### 矛盾

图形引擎为 60 FPS 百万级渲染,对特定业务流(如 A 股分时图 240 点)采用**预分配数组占位**(`BindIndexedColumn`)。这种内存优化绝不能反向污染 JSON 蓝图,否则低代码用户得理解列式存储。

### 解药:`ComponentMetadataRegistry`

蓝图编译期发现某 `DataSource` 类型在元数据表里登记了 `IPipelinePolicy`,编译器自动接管该数据源的管线装配,**蓝图层零感知**。

```csharp
// 业务侧自定义策略
public class TimeShareIndexedPolicy : PipelinePolicy<TimeShareDataSource, TimeData>
{
    protected override void CompileTyped(
        ChartBlueprint blueprint,
        TimeShareDataSource ds,
        UniversalDataPipe<TimeData> pipe,
        Func<Type, string, object> getOrCreatePort)
    {
        // 这里走预分配数组占位的高性能装配路径,而非通用反射
        // ...
    }
}

// 启动时登记
ComponentMetadataRegistry.Register<TimeShareDataSource>(new TimeShareIndexedPolicy());
```

策略命中后,`DynamicChartSchema` 的通用反射路径被完全绕开,蓝图 JSON 不需要任何变化。

### 戒律

- ❌ **禁止**在蓝图模型(JSON)里暴露性能相关参数(如 `IsFixedLength`)
- ✅ **必须**在 `ComponentMetadataRegistry` 里登记 DataSource 的管线编译策略,保持蓝图模型纯粹

## 5. SmartActivator 物化策略

[`SmartActivator.MaterializeTrait`](ComponentRegistry.cs):

| StyleModel 配置 | 行为 |
|---|---|
| 仅 `Properties` | 走 `Activator.CreateInstance(type)` + `InjectProperties` (传统 POCO) |
| 仅 `Preset` | 取 `type` 上 public static 字段/属性,直接复用单例(record / 位置参数 trait 适用) |
| `Preset` + `Properties` | 取预设实例后再覆盖部分字段(注意:可能污染共享单例,业务自负) |

`InjectProperties` 已支持 `JsonElement` 降级、Enum 字符串、`Nullable<T>`、`TypeConverter`、`IConvertible` 五重兜底,JSON 常见坑点全覆盖。

## 6. 当前局限

- `ComponentRegistry` 不区分作用域,JSON 中所有 `TypeName` 共享同一张全局表;多业务线复用蓝图时建议用 alias 区分。
- 含 ctor 复杂参数的 Feature(`AxisFeature(ITickProvider)` 已经在框架层用无参 ctor + init 属性铺平,见 §7;真要换 `ITickProvider` 实现仍需业务代码侧 new)。
- 闭包式参数(`Func<int>` / `Func<int, DateTime>` / `Action<...>` 等)JSON 表达不出来,典型例 `ScheduleTickProvider`、`OnRequireDataAsync` 仍需业务侧 wrapper 写死。

## 7. 可视化拖拽编辑器 (GraphViewer) — 已落地

> 实现位于 [`Hevo.Charting/LowCode/Designer/GraphViewer/`](GraphViewer/),业务侧入口
> [`GraphViewerBootstrap.Initialize()`](GraphViewer/GraphViewerBootstrap.cs)。

### 7.1 架构概览

GraphViewer 是 `ChartSchema` 的子类(**非 ReactiveSchema**),纯像素坐标系,5 层渲染管线:

| 层 | Z 槽位 | 职责 |
|---|---|---|
| `GraphCanvasLayer` | Background | 底色 + 自适应网格 + **类别泳道**(按节点 Y 范围动态合并出 6 条横向带子) |
| `GraphEdgeLayer` | Main | 贝塞尔连线(采样为 polyline,跨帧拖拽不会击穿渲染端的 SVG cache) |
| `GraphNodeLayer` | Main | 圆角矩形 + 标题栏 + 端口圆点(扇入端口画方块,字尾 `[]`) |
| `GraphSelectionLayer` | Selection | 选中描边 + 框选橡皮筋 |
| `GraphPreviewLayer` | Interaction | 拖出连线橡皮筋 + 端口悬停 tooltip(name / type / 注释) |

5 层共享同一个 `GraphRenderTrait(GraphState)` 实例,放各自 local bag —— `GraphState` 引用换新一发,`VisualDependencyTracker.CheckIfDirty` ReferenceEquals 一击命中,所有 layer 同帧 MarkDirty 重画。

### 7.4 蓝图协议扩展

[`ChartBlueprint.cs:DefineFeatures`](ChartBlueprint.cs) 现支持两种 port 形态:

| 形态 | JSON | 后端解析 |
|---|---|---|
| 单 `DataPort<T>` | `"DataPort": "global_price_id"` | `GetOrCreatePort` + 反射 SetValue |
| `DataPort<T>[]` 扇入 | `"ValuePorts": "id1,id2,id3"` (CSV) | 拆 CSV → 逐个 GetOrCreatePort → 反射写数组 |

GraphViewer 侧 [`GraphSerializer.ToBlueprint`](GraphViewer/GraphSerializer.cs):
- 检测 `Port.IsArray`,扇入端口所有 incoming edges 用 `string.Join(",", ids)` 编码
- **每个 Feature 自己的 OUTPUT 端口也写 PortBindings 字段**(关键 fix —— 否则像 `UniversalAutoScale.YRangePort` 这种 init=null 的写出端口字段一直是 null,Watch 回调 NRE 静默吞,axis/grid/line 全黑)
- DataSource 节点 `Properties` 字典除 `ScalarMappings/VectorMappings` 外的字段进 `bp.DataSource.Properties`,运行时 `SmartActivator.InjectProperties` 注入(支持配 `MinuteCeiling` 等 init 标量)

#### 7.4.1 端口类型严格化(防御性 GetOrCreatePort)

[`DynamicChartSchema.GetOrCreatePort`](ChartBlueprint.cs) 升级成类型严格版,签名 `object?`:

- 同一 portId 已被以另一个 T 注册过 → 返回 null + warning,不返回脏类型让 ctor 抛 ArgumentException
- 三处调用方(`CompileScalarMappings` / `CompileVectorMappings` / `DefineFeatures.PortBindings`)统一 null-check + skip
- `IPipelinePolicy` 自定义 pipeline 路径走 `?? throw`(类型对策略是已知的,冲突算 bug 显式暴露)
- `ScatterIngestor` 反射 ctor 改用 `ConstructorInfo.Invoke`(`Activator.CreateInstance` 对 `null` arg 会做类型推断,跟 `Func<TItem,int>?` 形参签名匹配失败抛 `MissingMethodException`)

GraphViewer 侧 `TryWire` (sample helper) 也加了 `Port.DataTypeName` 字符串相等校验,蓝图里类型不匹配的连线在拉的时候就拒掉,不污染 portRegistry。

#### 7.4.2 Viewport 节点 — schema 顶层 ViewportPorts 的可视化代理

`Viewport.LogicalLength` / `UserRange` / `ActiveRange` 是 schema 内部 ports,但**蓝图必须显式连**:`DataSource.LogicalLength → Viewport.LogicalLength` 这根线缺了 → ViewportManager 永远看到 length=0 → ActiveRange invalid → axis/series 早退黑屏。

为此引入 [`NodeKind.Viewport`](GraphViewer/GraphState.cs) + [`NodeFactory.CreateViewportNode`](GraphViewer/NodeFactory.cs):

- Viewport 节点不对应任何 .NET 类型,GraphSerializer 检测 edge 末端是 Viewport → globalId 强制走 well-known id (`VP_LogicalLength` / `VP_UserRange` / `VP_ActiveRange`)
- DataSource ScalarMappings 同步覆盖,ingestor 直接写到 schema 顶层 port
- `DynamicChartSchema` 构造时 `_portRegistry["VP_LogicalLength"] = this.Viewport.LogicalLength` 等预登记 → 任何使用 well-known id 的端口拿到的就是 schema 自己持有的 ViewportPorts 实例,**不创建副本** → 数据流通

LinkedDashboard 模式将来自动复用:`SchemaContext.AttachedProperty` 注入外部 `ViewportPorts`,`this.Viewport` 自动是注入的实例,同一行预登记代码自动指向共享端口,蓝图层零感知。

### 7.8 已知约束(设计期保留)

- **节点视觉自定义不能用 DataTemplate**:Layer 渲染是 `DrawOp` 指令缓冲。要每种节点长得不一样,要么手写 `DrawOp` 分支,要么走 `WidgetBuffer` 塞 UserControl。
- **trait 判脏粒度是引用级**:改 GraphState 必须 `with { ... }`,**不能原地 mutate**;否则 `VisualDependencyTracker.CheckIfDirty` 走的 `ReferenceEquals` 命中失败,UI 不重画。
- **连线类型校验**走 `Port.DataTypeName` 字符串相等(`"object"` 通配),拖拽时高亮"可连/不可连"。严格 .NET 类型语义校验未来再补。

### 7.9 BlueprintLauncher — 运行时上下文注入

[`BlueprintLauncher.Launch`](GraphViewer/BlueprintLauncher.cs) 签名:
```csharp
public static string? Launch(
    ChartBlueprint blueprint,
    Window? owner = null,
    object? dataSourceContext = null,                  // 路 A:类型化便捷
    Action<object>? configureDataSource = null);       // 路 B:万能回调
```

**两条互补的路注入数据源运行时上下文**(蓝图模型不携带的部分):

- **路 A**:`dataSourceContext` 类型化参数。Launcher 反射查 DataSource 上是否有 `LoadAsync(TContext)`,参数类型可赋值 → 自动 fire-and-forget 调用。`ReactiveDataSource<TSource, TContext, TItem>` 派生类全部命中。Window4 工具栏的"证券" TextBox 用这条路:用户填代码 → `Security.FromString` → `dataSourceContext`。
- **路 B**:`configureDataSource` 万能回调,LoadAsync 后同步执行,业务可自由处理(MinuteCeiling 配置、多步 Load 链、自定义 SwitchContext 等)。

| 类型 | 路 A | 路 B | 蓝图 Properties |
|---|---|---|---|
| `Security` 这种"运行时身份" | ✅ 类型化参数 | ✅ 回调 | ❌ 不该入蓝图 |
| `MinuteCeiling = true` 这种"产品化偏好" | ❌ | ✅ 回调可选 | ✅ DataSource.Properties 持久化 |
| 复杂多步 init | ❌ | ✅ 唯一选择 | ❌ |

### 7.10 Compute 节点抽象(为后续业务扩展铺路)

**蓝图层统一观点**:画布上任何"转换节点"都是 input port → 黑盒 → output port,底层用什么实现是细节:

| 节点性质 | 输入源 | 输出 | 现有底层 | 何时用 |
|---|---|---|---|---|
| **Source Ingestor** (Scalar/Vector) | `DataSnapshot<TItem>` | `DataPort<T>` | `ContextIngestor` / `ScatterIngestor` | snapshot 驱动,装在 `UniversalDataPipe` 链上 |
| **Compute Feature** | `DataPort<T>` | `DataPort<T>` | 派生 [`ComputeNodeFeature`](GraphViewer/Wrappers/LinkWrappers.cs) | board → board 纯计算 |
| **Side-effect Compute** | 多个 `DataPort<T>` | 多个 `DataPort<T>` | `ChartFeature.OnCompose` + `flow.Watch` | 写入链同步触发 (典型 UniversalAutoScale) |

⚠️ **Source Ingestor 不能等同 Compute Feature**:`ChartFeature.OnProject` 体系里只能读 board,看不到 `DataSnapshot<TItem>`。所以源端摄入必须装在 `UniversalDataPipe.Ingestor` 链上,蓝图侧通过 `DataSource.ScalarMappings/VectorMappings` 字段表达(已有协议)。Board → Board 转换才用 `ComputeNodeFeature`。

[`ComputeNodeFeature`](GraphViewer/Wrappers/LinkWrappers.cs) 模板:
```csharp
public abstract class ComputeNodeFeature : ChartFeature
{
    public override FeaturePhase Phase => (FeaturePhase)50;   // Layout 之后、Series 之前

    // 子类自己声明:
    //   public DataPort<T> InputPort { get; init; } = null!;
    //   [PortDirection(PortDirection.Output)]
    //   public DataPort<T> OutputPort { get; init; } = null!;

    protected sealed override void OnProject(FeatureContext ctx) => OnComputeProject(ctx);
    protected abstract void OnComputeProject(FeatureContext ctx);    // 读 input → 算 → 写 output
}
```

业务派子类(例 MovingAverage、PercentChange、Indicator 等)→ 注册 → picker 自动收录、画布自动可视化、NodeEditorWindow 自动认参数。**框架不动一行**。

### 7.11 Link 家族(传统 .Pipe() DSL 蓝图化对应)

[`Wrappers/LinkWrappers.cs`](GraphViewer/Wrappers/LinkWrappers.cs) 文件头标注 DSL ↔ 蓝图机制对应:

| 原 DSL | 蓝图机制 |
|---|---|
| `.Inject(ds => ds.PreClose).ForwardTo(P)` | `DataSource.ScalarMappings` + edge |
| `.Inject(ds => ds.LogicalLength).ForwardTo(VP.LogicalLength)` | 画布拉一根线到 Viewport 节点(§7.4.2) |
| `.LinkStream(cfg => cfg.AutoMap())` | `DataSource.VectorMappings` (auto) |
| `.Compute<S>(s, action)` | 派 `ComputeNodeFeature`(§7.10) |

剩下不能直接表达的:
- `Func<TIn, TOut>` 转换 lambda — JSON 写不出,只能业务派子类硬编码
- `Func<int>` / `Func<int, DateTime>` 等闭包参数(`ScheduleTickProvider`、`OnRequireDataAsync`)— 同上

## 8. 关键 fix 历史(本次落地的踩坑记录)

> 这些是把蓝图从"画布看着挺像"做到"运行起来真能渲染"必须修的硬骨头,记一下避免重蹈。

1. **GraphSerializer 漏写 OUTPUT 端口绑定**:`UniversalAutoScale.YRangePort` 的 init 默认值是 `null!`,蓝图必须显式焊一个 DataPort 实例。Serializer 之前只给 INPUT 边写 binding,导致 OUTPUT 字段一直是 null,Watch 回调 NRE 静默吞,axis/grid/line 全黑。Fix:每个 Feature 序列化时,自家 OutputPorts 也写 `PortBindings` 字段,跟下游 input 共享同一全局 portId(同 `GetOrCreatePort` 缓存)。
2. **DynamicChartSchema 漏写 Viewport.LogicalLength**:每个传统 schema 都 `.ProjectExtent(Viewport)` 把 `ds.LogicalLength` 写到 `Viewport.LogicalLength`,缺它则 ViewportManager 看到 length=0 → 写 `default(RealRange)` → 全部下游早退黑屏。后来升级成 Viewport 节点 + well-known id,蓝图侧画一根线显式表达。
3. **ScatterIngestor ctor 类型推断失败**:`Activator.CreateInstance(Type, params object[])` 对 `null` 参数(`indexSelector`)无法反推 `Func<TItem,int>?` 形参签名,抛 `MissingMethodException`。Fix 改用 `ConstructorInfo.Invoke` 直接按位置塞参数。
4. **端口类型 cache 冲突**:同一 portId 被两个不同 T 的端口请求(例 Time:DateTime 错连到 *:double),`GetOrCreatePort` 之前返回缓存的脏类型,ctor 抛 ArgumentException 把整张图带崩。Fix:类型严格化,签名改 `object?`,冲突返回 null + warning,调用方 skip;`TryWire` (sample) 也加 `DataTypeName` 校验。
5. **Edge 渲染同 source 多线视觉重叠**:同一 OutputPort 派出多条边时,贝塞尔起点重合 → 看起来像一根。Fix:`GraphEdgeLayer.OnUpdate` 维护 `(fromNodeId, fromPortId) → 已绘次数` 计数,第 N(≥1) 条线纵向偏移 ±8*N px(交替正负),曲线分散开。同时 `DrawBezier` 控制点逻辑加强:反向边(b.X &lt; a.X)的水平 dx 拉到 `max(120, dy*0.6+dx*0.5)` 防 S 太紧穿点;陡边(|dy| &gt; |dx|*1.5)的 dx 拉大避免视觉直角。
6. **Edge 被中间 node 遮挡 → 数据流可见性断**:画布上 edge 起止节点之间常常路过别的 node,默认贝塞尔直行被遮成两段。Fix 三件套:
   - `GraphEdgeLayer` 移到 `GraphNodeLayer` **之上**(同 Main 槽位,后加),数据流连续可见性优于节点视觉完整性(参 Houdini / n8n / Unreal Blueprint 惯例)。
   - `GraphEdgeLayer.ComputeAvoidanceVOffset` 扫所有非端点节点,如果 AABB 横向跟边重叠且节点中心 Y 与边在该 X 处的预期 Y 距离 ≤ `halfH+16px` 安全垫,把控制点 Y 推开,曲线腹部绕到节点上方/下方。多障碍取推力最大方向,限幅 ±180 px。
   - 双笔渲染:深色半透明 outline (3px) 在底层兜底"过浅色节点头部也能看见",上层亮色 EdgePen (1.5px) 表达连接关系本身。
7. **AutoLayout 列分组 → 类别横幅全重叠**:旧版按 Category 分**列**,每列从 y=60 起头独立排开 → `GraphCanvasLayer.ComputeCategoryBands` 按节点 Y 范围聚合横幅,所有 category 都覆盖 y=60 起的范围 → 视觉上横幅完全重叠,UX 报废。Fix:改成按 Category **横向泳道**,每泳道独占自己的 Y 行,内部按入度+barycentric 双模式优化:单节点泳道(DataSource/Axes/Series)自由 X = 邻居平均(让"主线"上下游对齐成竖直线);多节点泳道(Environment/Interaction)整体平移对齐外部连接重心,内部 indeg 顺序不动。迭代 5 轮收敛。详见 [`GraphDeserializer.AutoLayout.Apply`](GraphViewer/GraphDeserializer.cs)。
8. **连线像折线(贝塞尔采样成 polyline)**:`GraphEdgeLayer.DrawBezier` 把三次贝塞尔手动采样成 18 段 polyline 后走 `IDrawingSink.DrawPolyline`,长边上每段 50px+ 的直线段视觉上能看到折角,曲线像锯齿。Fix:加 `DrawOp.DrawCubicBezier` 原生贝塞尔指令([Primitives.cs](../../Renderers/Primitives.cs)),WPF 端用 `StreamGeometryContext.BezierTo` 走 GPU 抗锯齿曲线管线([DrawingRenderer.BuildCubicBezier](../../Renderers/DrawingRenderer.cs)),任何长度都丝滑;DrawBezier 直接调 `draw.DrawCubicBezier(pen, p0, c1, c2, p3)` 不再手算采样。
9. **AutoLayout 反向边导致"S 钩"弯折**:旧版按 indeg 或 barycentric 排,孤立配置节点(decor/grid/vpManager 这种没 Port 也没 edge 的)占住 col 0-3,把真正的连接节点 scale 顶到 col 4;但 line/yAxis(scale 的下游消费者,在另一泳道)的 col 是 2 → 边 (scale, line) 从 col 4 反向连到 col 2,贝塞尔回钩成 S。Fix:[`ComputeDepth`](GraphViewer/GraphDeserializer.cs) 算每个节点的 DAG 深度(Kahn 拓扑序最长路径),泳道内排序按 (是否有 edge → depth → alphabetic),孤立节点推到泳道末尾;col 派位用 `max(node.depth, lastColInLane + 1)` 强制 col ≥ 深度。任何 edge (a→b) 天然 a.col < b.col,完全消除反向。
10. **JSON 预览/导入对 NaN/Infinity 炸**:业务数据源经常带 `double.NaN` 这种"程序员默认值"(典型 [TimeShareDataSource.PreClose](../../../Hevo.Drawing/TimeShare/TimeShareDataSource.cs)),NodeEditorWindow 反射读出来塞进 Properties 字典 → `JsonSerializer.Serialize` 默认行为是 `InvalidOperationException("infinity cannot be written as valid JSON")`。Fix 两件套:
    - Window4 共享一份 `JsonSerializerOptions` 加 `NumberHandling = AllowNamedFloatingPointLiterals`,导出/导入两端复用,NaN 写成 `"NaN"` 字符串(System.Text.Json 标准扩展)。
    - NodeEditorWindow `MakeEditorByType` 的 TextBox 路径加 `IsSpecialFloat` 判断,NaN/Infinity 一律按空串显示;用户留空 → CoerceTextValue 返回 null → SmartActivator.SafeChangeType 写非 nullable double 失败被静默吞,目标对象保持原默认值。
