# 📝 Hevo.Charting 代码注释准则 (v3.0)

> **核心哲学**：关键逻辑不落空，废话半句都不多。
> 注释的唯一价值在于解释 **“为什么（Why）”** 和 **“意图（Intent）”**，而不是翻译 **“是什么（What）”** 的语法。

---

## 💡 准则一：意图导向，拒绝“废话文学”

永远不要把 C# 语法翻译成中文。注释应当说明这段代码在 **业务链路** 或 **架构约束** 中的真实作用。

* **❌ 反面教材（翻译语法）**：
    ```csharp
    // 如果 range 无效，就 return
    if (!range.IsValid) return; 
    ```
* **✅ 标准示范（阐述意图）**：
    ```csharp
    // 💥 0-GC 短路拦截：数据不足或未初始化时直接退帧，防止无效计算击穿底层渲染
    if (!range.IsValid) return; 
    ```

---

## 💡 准则二：死磕“魔法数字”与“数学公式”

图表引擎涉及大量的像素换算与坐标投影。任何脱离上下文的常量（如 `0.5`, `12`）或复杂的数学计算，**必须**配有推导注释。

* **❌ 反面教材（不明所以的常量）**：
    ```csharp
    double padding = maxDiff * 1.1; 
    ```
* **✅ 标准示范（标注物理意义）**：
    ```csharp
    // 叠加 10% 的安全边距 (PaddingRatio)，防止 K 线极值点紧贴画板上下边缘
    double padding = maxDiff * (1 + PaddingRatio); 
    ```

---

## 💡 准则三：标明“架构红线”与“物理约束”

当代码涉及到违背常规直觉的写法（例如：为了遵守 Hooks 铁律、绕开系统 Bug 或执行极致优化时），必须用 `// 💥` 醒目标记，警告后人不可轻易重构。

* **✅ 标准示范（同步架构铁律）**：
    ```csharp
    // 💥 铁律：必须在顶层无条件解包 UsePort！严禁放入分支，防止触发 HEVO003 游标错乱
    var (range, _) = ctx.UsePort(RangePort);
    ```

---

## 💡 准则四：解释“响应式依赖”的触发边界

在使用 `UseDynamicMemo` 或其他响应式流时，必须简要说明 **“什么情况下会重算”**，这对于排查性能瓶颈至关重要。

* **✅ 标准示范（依赖说明）**：
    ```csharp
    // 缓存刻度。依赖 plotArea 和 range，当且仅当窗口拉伸或数据量程变化时触发重算
    var (ticks, ticksChanged) = ctx.UseDynamicMemo("AxisTicks", (range, plotArea), deps => { ... });
    ```

## 🛠️ AI 协作指令 (AI Prompt Instruction)

为了让 AI 在生成代码时保持这种“专业且克制”的注释风格，请在开启新任务时使用以下唤醒词：

> **“请输出代码，并严格遵守『Hevo 注释准则』：只注核心意图、魔法数字、架构铁律与防御性短路，拒绝翻译语法的废话注释。”**

### 📌 快速自检清单 (Checklist)
1. [ ] **是否有“翻译”语法？** (如有，请删除)
2. [ ] **魔法数字是否有物理含义？** (如 `0.5` 是否标注了“中心偏移”)
3. [ ] **复杂的 `if` 逻辑是否有业务理由？**
4. [ ] **Hooks 调用位置是否加了“铁律”警示？**
5. [ ] **生命周期敏感代码**（`OnSuspend / OnResume / Dispose`）**是否注明"Phase 11 / §H"并说明为何需要手动处理**？（基类已自动处理 IPausable 资源，只有非标准资源才需重载；注释必须说明"为什么基类不够"）
